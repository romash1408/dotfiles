# Скрейпинг скроллируемого списка Android-приложения через adb

Подход: не OCR и не скриншоты, а дерево интерфейса (`uiautomator dump`). Текст, `resource-id`, `content-desc` и координаты берутся прямо из view-иерархии, поэтому распознавать ничего не нужно. Скрипт листает список свайпами и сохраняет дамп каждого экрана. Потом дампы склеиваются по перекрытию в одну упорядоченную последовательность.

Файлы скилла:
- [scrape.py](scrape.py) — листает список и сохраняет дампы экранов;
- [merge.py](merge.py) — разбирает дампы и склеивает экраны по перекрытию в одну последовательность `(заголовок, поля элемента)`.

Под конкретное приложение пишется только последний шаг: превращение полей в колонки CSV. Пример для О!Банка (`kg.o.nurtelecom`) — `build.py` в проекте obank-scrab.

## 1. Разведка

```bash
adb devices -l
adb shell dumpsys window | grep -E 'mCurrentFocus|mFocusedApp'   # какое Activity на экране
adb shell wm size                                                 # разрешение для координат свайпа
adb exec-out uiautomator dump /dev/tty > dump0.xml                # дамп текущего экрана в stdout
```

- `uiautomator dump /dev/tty` пишет XML прямо в stdout, без файла на телефоне. В конце бывает мусор вроде `UI hierachy dumped to...`, поэтому вырезайте от `<?xml` до `</hierarchy>`.
- Выведите все узлы с непустыми `text`, `content-desc`, `resource-id` или `scrollable="true"` и разберитесь со структурой:
  - найдите контейнер списка (`scrollable="true"`, у О!Банка это `rvDetalization`, RecyclerView);
  - проверьте, что лежит среди его **прямых детей**: элементы-обёртки (ViewGroup) и заголовки-разделители (TextView с датой: «26 августа», «Сегодня», «Вчера»);
  - определите поля элемента по `resource-id`: `tv_title`, `tv_subtitle`, `tv_value`, `tv_time`, `tv_additional_info` (ID), `tv_status`;
  - посмотрите `content-desc` у карточки (accessibility-строка). Там часто есть всё сразу, включая детали, которых нет в text-полях (например, «Возврат»).

## 2. Сбор (scrape.py)

Пользователь открывает в приложении нужный экран и сам прокручивает список до стартовой точки (например, до самой ранней даты периода). Затем запустите скрипт в фоне:

```bash
python3 .claude/skills/adb-scrape-list/scrape.py rvDetalization --dir dumps --direction up > scrape.log 2>&1
```

- `container` — `resource-id` контейнера списка без пакета (из разведки).
- `--direction up|down` — куда листать: `up` = к более новым записям сверху.
- `--swipe-ms` (1500), `--pause` (0.8), `--max-screens` (2000).

Цикл такой: дамп → `dumps/NNNN.xml` → свайп примерно на 45% высоты экрана (координаты берутся из `wm size`) → пауза → повтор. Скрипт останавливается, когда содержимое списка в двух дампах подряд совпало, то есть достигнут край.

Подводные камни:
- **Инерция (fling).** Быстрый свайп (`... 400` мс на 1200 px) прокручивает больше экрана, и элементы пропадают. Делайте свайп медленным (~1500 мс) и короче высоты списка. Потом проверьте, что соседние дампы пересекаются хотя бы на 2–3 элемента по ID.
- **Блокировка экрана.** Если телефон погас, дамп вернёт `com.android.systemui` / `NotificationShade` без вашего списка. Скрипт не должен свайпать вслепую: если контейнер списка не найден, пусть ждёт и печатает «разблокируйте телефон». Проверить состояние: `dumpsys power | grep mWakefulness`. **Не меняйте системные настройки** (`stay_on_while_plugged_in` и т.п.), попросите пользователя разблокировать. Во время работы свайпы сами держат экран активным.
- Сохраняйте **сырые дампы** на диск. Тогда парсер можно переписывать сколько угодно без повторного скролла. Первая версия парсера почти наверняка будет неправильной.
- Запускайте в фоне с логом и следите за прогрессом. Ориентир: ~4 новых элемента на свайп, месяц банковской истории — около 60 экранов.

## 3. Разбор одного дампа (merge.py → `parse_screen`)

Идите по **прямым детям** контейнера списка в порядке следования:
- `TextView` с текстом — это заголовок (дата);
- обёртка — это элемент: соберите `text` всех потомков по `resource-id` и `content-desc` карточки.

Частично видимые элементы у краёв экрана **пропускайте**, если в них нет ключевого поля (ID). Благодаря перекрытию они целиком попадут на соседний экран. У одного и того же элемента на разных экранах оставляйте версию с наибольшим числом полей.

## 4. Склейка экранов (merge.py)

Как библиотека — основной вариант. Ключевую функцию задаёте под приложение:

```python
import re, sys
sys.path.insert(0, '.claude/skills/adb-scrape-list')
from merge import load_screens, merge

def key_fn(f):  # f = {resource-id: text, ..., '_desc': content-desc'и через ' | '}
    m = re.search(r'ID: (\d+)', f.get('tv_additional_info', ''))
    return m.group(1) + f.get('tv_value', '')[:1] if m else None   # None = частично видимый, пропустить

items = merge(load_screens('dumps', 'rvDetalization', key_fn), direction='up')
# [(header, fields), ...] сверху вниз по списку; header — последний заголовок выше элемента (дата)
```

Через CLI выводится JSON Lines, сверху вниз:

```bash
python3 .claude/skills/adb-scrape-list/merge.py dumps rvDetalization --key-field tv_additional_info --key-regex 'ID: (\d+)' --key-extra tv_value > items.jsonl
```

`--key-extra` дописывает к ключу значения других полей, если ID сам по себе не уникален (см. раздел 5).

Алгоритм: каждый экран — упорядоченный список ключей (тексты заголовков и ключи элементов). Все ключи уникальны, поэтому склейка такая:

```python
G = keys(screens[-1])                    # самый верхний экран (листали вверх)
for s in reversed(screens[:-1]):         # спускаемся вниз
    idx = последняя позиция в s ключа, который уже есть в G   # нет такого → assert: был пропуск
    G += [k for k in s[idx+1:] if k not in G]
```

Затем `merge` проходит по `G` сверху вниз и присваивает каждому элементу последний встреченный заголовок. Если листали вверх, для хронологического порядка разверните результат.

`assert` на отсутствие перекрытия обязателен: только он гарантирует, что ничего не пропущено.

## 5. Ловушки данных (найдены на практике)

- **ID не уникален.** Возврат (`+133,89`, в content-desc «Возврат») приходит с тем же ID, что и исходное списание (`-133,89`). При ключе «только ID» одна запись затирает другую. Используйте составной ключ: `ID + знак суммы`. После исправления в выгрузку добавились 3 потерянные операции.
- **Поля только в content-desc.** Пометка «Возврат» есть только в accessibility-строке. Достаётся регэкспом между суммой и `ID:`.
- **Статус.** `tv_status` («В обработке») есть только у части элементов. Выводите отдельной колонкой и не дублируйте в примечание.
- **Даты без года.** Заголовки «26 августа» года не содержат, подставьте текущий (осторожно на стыке лет). «Сегодня» / «Вчера» пересчитайте от текущей даты.
- **Суммы.** `-1 460,44 c`: убрать пробелы и неразрывные пробелы (`\xa0`), заменить запятую на точку, `c` → `KGS`. Сырую строку оставьте отдельной колонкой.
- Логируйте `resource-id` с текстом, которые парсер не знает (`Counter`). Так находятся поля вроде `tv_status`.

## 6. Проверка результата

- нет строк без даты, суммы или времени;
- первая и последняя даты совпадают с ожидаемым диапазоном;
- граничные элементы первого экрана (включая частично видимые) есть в CSV;
- дубликаты ID разобраны вручную: это реальные пары или ошибка склейки;
- распределение операций по дням и суммы поступлений и списаний выглядят правдоподобно.

CSV пишите в `utf-8-sig`, чтобы Excel корректно открыл кириллицу.

## Безопасность

Только чтение: дамп UI и свайпы по списку. Не нажимать на элементы (переводы, платежи), не вводить PIN или пароли, не менять настройки телефона. Если нужна разблокировка, её делает пользователь.
