# Синхронизация выписки О!Банка с таблицей money

Агент сам листает выписку на телефоне, сверяет её с листом «Операции» и вставляет
недостающие операции. В конце он выдаёт короткий отчёт. Категории проставляет и
синхронизирует с ZenMoney пользователь.

Файлы скилла:
- `scrape.py` листает список и сохраняет uiautomator-дампы экранов;
- `merge.py` склеивает экраны по перекрытию;
- `obank.py` превращает дампы О!Банка в `bank.json` (дата с годом, сумма, статус, возврат, зачёркнутая);
- `money.py` работает с таблицей: `sync`, `reconcile`, `plan`, `insert`, `fix-amount`;
- `sync.md` — **как устроены таблица и синк money-sync** (колонки, что синк делает со строками,
  от чего он падает). Прочитайте до первой записи: репозитория рядом может не быть, гадать нельзя;
- `credentials.json`, `.env` — секреты: ключ сервисного аккаунта Google, `SPREADSHEET_ID`,
  `SYNC_SECRET`. В chezmoi они хранятся зашифрованными, наружу их не выводить;
- `reference.md` — общая техника adb-скрейпинга и ловушки, найденные на практике.

Рабочие файлы (дампы, json) складывайте в scratchpad, а не в репозиторий.
Ниже `$S` — каталог этого скилла, `$PY` — Python с библиотекой Google API (см. ниже).

## 0. Окружение

Репозиторий money не нужен: всё необходимое лежит в скилле.

- **Таблица.** `money.py` берёт `credentials.json` и `.env` из каталога скилла. Если их там нет,
  ищет их в `MONEY_DIR` или `~/projects/money`. Переменные окружения `SPREADSHEET_ID`,
  `GOOGLE_CREDENTIALS_FILE`, `SYNC_SECRET` важнее файлов. Если ключа нет нигде, остановитесь и
  спросите пользователя (вероятно, chezmoi не расшифровал секреты).
- **Python.** `obank.py`, `scrape.py` и `merge.py` работают на стандартной библиотеке.
  `money.py` нужен `google-api-python-client`, поэтому держите для него отдельный venv:
  ```bash
  PY=~/.cache/adb-scrape-list/venv/bin/python
  [ -x $PY ] || { python3 -m venv ~/.cache/adb-scrape-list/venv && ~/.cache/adb-scrape-list/venv/bin/pip -q install google-api-python-client; }
  ```
- **Синк** — `http://hp.wg:8090/sync`, домашний сервер через WireGuard. С любой машины адрес
  один и тот же, он зашит по умолчанию (переопределить можно через `SYNC_URL`). Если `hp.wg`
  недоступен, это стоп: попросите пользователя поднять WireGuard.
- **Телефон.** `adb devices -l`. Если устройств несколько (например, висит офлайн-эмулятор),
  выберите физическое и выставьте `export ANDROID_SERIAL=<serial>` для всех команд. Если
  устройство `unauthorized`, попросите пользователя подтвердить отладку на телефоне.

## 1. Проверки перед стартом (при любой ошибке — стоп)

1. `adb shell dumpsys window | grep mCurrentFocus` должен показывать
   `kg.o.nurtelecom/wallet.ui.detailing.WalletDetailingActivity`. В дампе экрана
   (`adb exec-out uiautomator dump /dev/tty`) должен быть контейнер `rvDetalization`, а в
   заголовке — карта «Visa Cashback». Это счёт `O!Bank R *3720` в таблице; другой счёт задаётся
   через `MONEY_ACCOUNT`.
   - Экран входа (`FingerPrintActivity`, BiometricPrompt): попросите пользователя
     разблокировать приложение. PIN и отпечаток не вводить никогда.
   - Другой экран: попросите открыть выписку. Для старых дыр пользователь сам выставляет
     дату через календарь в шапке.
2. `$PY $S/money.py sync`. Команда должна вывести ответ сервиса и статус `OK …` из D1. Код ≠ 0
   означает стоп: пользователь разбирается с синком сам.

## 2. Цикл: листать вниз порциями и сверять

Листайте **вниз**, к более старым операциям, от того места, где пользователь открыл выписку.
Обычно это «Сегодня», а для дыр — выбранная дата.

```bash
python3 $S/scrape.py rvDetalization --dir dumps --direction down --max-screens 20 --start 0
python3 $S/obank.py dumps > bank.json
$PY $S/money.py reconcile bank.json        # отчёт по дням + последняя строка «СТОП: …»
```

Следующая порция: `--start 20`, `--start 40` и так далее, в ту же папку. Первый кадр новой порции
повторяет последний кадр предыдущей, перекрытие склейке не мешает. 20 экранов — это примерно
2–3 дня операций.

**Когда остановиться.** `reconcile` печатает `СТОП: полностью покрытый день X`. Это первый
сверху непустой день, где все операции уже есть в таблице. Самый нижний день порции может быть
обрезан, поэтому решение по нему не принимается. Пока стопа нет, листайте дальше. Если пользователь
задал период, листайте, пока не пройдёте его начало.

Как `reconcile` сопоставляет операции (по колонке «Сумма в валюте счёта» строк счёта; строки
с «Удалена = TRUE» исключены):
- **пропуски:**
  - зачёркнутая операция: сумма без знака, `8 252,83 c`;
  - возврат с пометкой «Возврат» вместе с возвращённым списанием (тот же ID банка);
  - пара «приход и расход на одну сумму» у одного контрагента в один день;
- **точная сумма:** тот же день, затем ±1 и ±2 дня. Операции «плывут» по дате, особенно около полуночи;
- **склейка:** несколько операций банка записаны одной строкой (два проезда по 17 — строка 34;
  пять пополнений — одна строка);
- **разбивка:** одна операция банка записана несколькими строками. Сюда же попадает «покупка
  минус кешбэк» отдельной строкой: Глобус −139,59 = −680,49 + 540,9; «Мобильная связь О!»
  −39,61 = −1 − 199 + 160,39;
- **оплата бонусами:** «Покупка на кассе №N, Глобус…» в выписке на меньшую сумму, чем в таблице
  (в таблице записана полная покупка);
- **конвертация:** сумма отличается до 5%, а строка таблицы — с конвертацией валют. Такая строка
  уходит в кандидаты на правку суммы.

Группы скрипт подбирает жадно, поэтому глазами проверьте строки «склеена» и «разбита»: они
должны выглядеть правдоподобно (контрагент, время, описание).

## 3. Запись

```bash
$PY $S/money.py plan bank.json > plan.json   # черновик для операций новее дня СТОП
# просмотрите и поправьте plan.json
$PY $S/money.py insert plan.json             # сухой прогон: куда встанет каждая строка
$PY $S/money.py insert plan.json --go        # одна атомарная запись + проверка
$PY $S/money.py fix-amount <id> <сумма> [--account-sum] [--go]   # для кандидатов «конвертация»
```

Правила пользователя (в коде уже заложены, при правке плана не нарушать):
- **Существующие строки не трогать и не переставлять, только вставлять.** Новая строка встаёт
  в свой день по времени: время выписки (Бишкек, UTC+6) сравнивается с `created` соседей.
  Если соседи стоят не по порядку, их не трогать.
- У новых строк «Новая» = TRUE (пользователь потом проходит их руками), в колонке R стоит `suggested`.
  R — личная пометка пользователя, синк её не читает.
- **Категории не выдумывать.** Исключение — пользователь сам назвал категорию (например,
  «48 300 — это квартплата»: «Аренда», USD −550, в валюте счёта −48 300, как у прошлых
  квартплат). Точное имя берите из колонки «Для операций» листа «Категории».
- **Получатель** — только при однозначном соответствии в истории. `plan` ставит его, если
  сырая строка банка ≥ 2 раза и в ≥ 80% случаев за год записывалась этим получателем. Иначе
  контрагент идёт в описание в стиле пользователя: `<контрагент> в HH:MM`. Опечатку банка
  можно сопоставить вручную, если сомнений нет (`UNIQUMSPORT` → `UNIQUM SPORT`). Разовое
  совпадение (Таалай М. однажды записан как «шоро») — не повод ставить получателя.
- Статус «В обработке» дописывается в описание.
- **«Перевод между своими счетами» +X** уже есть в таблице, если там есть перевод на ту же сумму
  в тот же день; это проверяется обычной сверкой. «MBANK по номеру телефона» −X **не обязательно**
  перевод себе: так платят и другим людям. Сами переводы из таких пар не делать.
- **Правка суммы при конвертации.** Если сумма поменялась после обработки банком, `fix-amount`
  меняет «Сумму» (I) и ставит `suggested`. «Сумму в валюте счёта» (M) не трогает: по ней
  пользователь откатит правку, если она неверна. Синк возьмёт новую «Сумму», когда валюта строки
  совпадает с валютой счёта. Для строки в чужой валюте правьте M, а не I (`--account-sum`).
- **Старые дыры.** Пользователь закрывал их строкой «Корректировка». `reconcile` перечисляет
  корректировки в диапазоне: после заполнения дыры их нужно пересчитать или удалить. Это решает
  пользователь, сами не трогайте.
- Спорное не решать молча, а вынести в отчёт: разница в десятки сомов без конвертации,
  положительная POS-операция, подозрение на дубль. Строки с «Удалена = TRUE» — это удалённые
  дубли, о них не писать.

## 4. Отчёт пользователю

Коротко, по делу:
- где остановились и почему (`день X — всё есть`); какие пропуски распознаны (зачёркнутые,
  возвраты, отмены);
- сколько строк вставлено; по дням — что вошло, с пояснениями только для неочевидного
  (получатель по опечатке, бонусы Глобуса, крупные переводы без пары);
- правки сумм (`строка N: было → стало, в M осталось старое`);
- что проверить руками: спорные сопоставления, корректировки в диапазоне;
- последняя строка: «Можно проставлять категории и синхронизировать».

## Безопасность

С телефоном только чтение: дампы UI и свайпы по списку. Не нажимать на элементы, не вводить
PIN и пароли, не менять настройки телефона. В таблице только вставки, `fix-amount` и пометка R.
Удалять и переставлять строки нельзя.
