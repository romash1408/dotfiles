# Машина hp: память общая с сервисами

hp — домашний сервер-ноутбук (19 ГиБ RAM). На нём же работают immich, jellyfin,
AdGuard (DNS всего дома), CI-раннеры и десктоп. 29.10.2026 тесты агента в
`docker run` съели остаток памяти, и hp на полчаса перестал отвечать — даже по ssh.
Поэтому для любых тяжёлых прогонов здесь действуют правила:

- **Каждый `docker run` для тестов, сборок и временных БД — с лимитом и в `ci.slice`:**
  `docker run --memory=3g --memory-swap=3g --cgroup-parent=ci.slice …`
  В compose: `mem_limit: 3g`, `memswap_limit: 3g`, `cgroup_parent: ci.slice`.
  `ci.slice` — общий бюджет CI (6 ГиБ, под systemd-oomd): при нехватке убивается
  контейнер, а не зависает хост. Без `--cgroup-parent` контейнер попадает в
  `system.slice` к сервисам, где его не ограничивает ничто.
- **Тяжёлое вне docker** (`dotnet test`, gradle, JVM, сборки) — тоже под лимит:
  `systemd-run --user --scope -p MemoryMax=3G -p MemorySwapMax=0 <команда>`.
- **Прогоны — по одному**, не параллельно. Перед тяжёлым прогоном — `free -h`:
  если `available` меньше 4 ГиБ, не запускать, а сообщить пользователю.
- **Временные контейнеры не оставлять**: после работы `docker rm -f` (тестовый
  postgres однажды прожил 39 часов). Долгоживущие сервисы — только через ansible
  (репозиторий infra), не руками.
- Если контейнер убит по OOM (`docker inspect` → `OOMKilled: true`) — не поднимать
  лимит молча: сказать пользователю, сколько нужно и почему.
