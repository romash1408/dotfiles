# Рабочий Mac: Borg-бэкап и переезд через backup

Источник истины — текущий Mac, не давно потерянный dev. Репозиторий BorgWarehouse
`work-mac`, имя `fb6e66fe`, Borg 1.x. Репозиторий шифруется на клиенте.
Данные идут через существующий `ssh backup` к WG-порту VM; WireGuard на Mac не нужен.
Конфигурация, SSH transport, код сборщика и launchd находятся в chezmoi.

## Ключи и запуск

`~/.config/mac-backup/passphrase`, `borg-key.export` и `~/.ssh/borg_work_mac`
имеют права 600. Их age-зашифрованные копии хранятся в chezmoi. Age-ключ уже
сохранён в rbw как `chezmoi-age-key`. Дополнительная запись `work-mac-borg`
предназначена для Borg-пароля, экспорта ключа и отдельного SSH-ключа репозитория;
состояние её синхронизации нужно проверять при передаче машины.
Секретов в этой инструкции и незашифрованном git нет.

```
mac-backup run
mac-backup status
mac-backup list
mac-backup check
mac-backup restore --archive <точное-имя> --target ~/mac-restore
```

Restore извлекает в НОВЫЙ каталог и проверяет SHA256 файлов и SQLite quick_check.
Он никогда не заменяет работающий HOME. Имя snapshot заканчивается на `complete`
или `partial`: частичный снимок сохраняет доступные данные, но не считается успехом.

Обычный снимок онлайн: SQLite backup API, для занятой Chromium SQLite — неизменившийся
набор DB/WAL/journal с восстановлением и проверкой ТОЛЬКО копии; JSONL фиксируется
по длине и обрезается на последней полной строке. Исходные данные не редактируются.
Все разговоры берутся из хранилищ, независимо от наличия в Herdr и herdr-history.

Сохраняются `~/.codex` (включая sessions, archived_sessions, state/thread_history
и другие SQLite), `~/.claude`, `~/.claude.json`, стандартные профили
`~/Library/Application Support/{Codex,Claude}`, Herdr/Ovis/history/HTML, локальные
скрипты, конфиги и Direct-транспорт. Кэши браузера, node_modules, IPC/sockets/locks
и Python venv не переносятся. Desktop-приложения получают профиль в своём штатном
месте; сессии не отправляются в отдельные `CODEX_HOME`.
Обычные облачные чаты Claude принадлежат аккаунту: локальный профиль не является
полным экспортом истории облака. Если нужен автономный архив таких чатов,
нужен штатный экспорт данных аккаунта в дополнение к этому снимку.

Это бэкап агентской рабочей среды, а не полный образ всех документов/фото/VM.
Git-проекты и прочие личные файлы нужно включать отдельным согласованным набором,
проверив объём и исключив Arc/FUSE и сборочные кэши; VM backup уже перевезена.

## Arc: состояние и единая раскладка

`recovery/arc-mounts.json` содержит ВСЕ регистрации. Для смонтированной копии
экспортируются полный HEAD/ветка, staged/unstaged binary patch, dirty/untracked
файлы с SHA256 и удаления; HEAD/status повторно сверяются. Для размонтированной
копии сохраняются refs и `.overlay_v2` с локальными изменениями, без object store,
журналов и устаревших runtime-locks. Сам бэкап не монтирует и не меняет копии.
Все FUSE операции выполняются в ограниченном по времени дочернем процессе.

В каждом `recovery/arc/*/manifest.json` есть `source`, `target`, `info`, `complete`.
Целевая раскладка: `/Users/dubiner/arcadia` + `/Users/dubiner/arcadia-wt/<имя>`.
Разные исходные копии НЕ объединять: даже менеджеры могут иметь разные HEAD/ветки.
Для нескольких копий использовать ОДИН общий object store Arc на новом Mac.
Object cache не бэкапится: коммиты получают с сервера по полным hash.
Старые overlays сначала сохранить неизменными; не заменять их новым overlay и не
вызывать reset/clean. Восстановление выполнять по текущему Arc skill/CLI с
сохранением ветки, staged/unstaged и untracked. Unmounted-store — страховая копия
локального состояния, не инструкция копировать её поверх существующего mount.

## Переезд

Независимый стартовый комплект лежит на `backup:~/mac-recovery/bootstrap`:
git bundle chezmoi, эта инструкция, контрольные суммы, открытая конфигурация
транспорта и age-зашифрованные Borg/SSH-ключи. Он доступен до расшифровки Borg;
незашифрованных ключей на backup нет. Комплект обновляется при изменении настройки,
а актуальные сессии берутся из регулярных Borg-архивов.

На новом Mac сначала установить `borgbackup` 1.x, `chezmoi`, Python и настроить
`ssh backup`. Затем:

```
umask 077
scp -r backup:mac-recovery/bootstrap ~/mac-bootstrap
cd ~/mac-bootstrap
shasum -a 256 -c SHA256SUMS
```

Восстановить существующий `chezmoi-age-key` из rbw/Bitwarden в
`~/.config/chezmoi/key.txt` (не выводить ключ в терминал), права 600. Выполнить
`sh ~/mac-bootstrap/bootstrap.sh`: он установит ТОЛЬКО клиент резервного копирования
и ключи, без запуска Herdr, chezmoi apply и таймеров. Существующие файлы с иным
содержимым скрипт отказывается заменять. После этого `mac-backup list` и restore
доступны. Git bundle можно клонировать в НОВЫЙ каталог, изучить и затем установить
как source chezmoi. Не делать слепой полный apply поверх уже восстановленных данных.

1. На новом Mac использовать тот же `/Users/dubiner`. Настроить корпоративный
   доступ, Arc, Skotty и `ssh backup`; установить совместимые клиенты Borg/Codex/Claude/Herdr.
   Секреты и exact chezmoi source можно извлечь из снимка в отдельную папку.
2. Взять точный последний `complete`, извлечь и проверить. Читать manifest и
   предупреждения; наличие архива само по себе не доказывает полноту.
3. Создать рабочие копии по карте source→target. Проверить ветки/полные HEAD,
   staged/unstaged изменения, удаления и untracked. Установить скиллы штатным
   `junk/dubiner/ai-global/install.sh`; не сохранять активную ссылку на старый Mac.
4. Перед финальным снимком на старом Mac приостановить задачи, дождаться команд,
   закрыть desktop-приложения и писателей Codex/Claude. Сохранить финальный
   Herdr session.json до остановки сервера. Сделать свежий complete и проверить restore.
5. На новом Mac закрыть всех писателей до установки баз. Восстанавливать в
   обычные `~/.codex`, `~/.claude` и vendor desktop paths. Если там уже есть новые
   разговоры — сначала сохранить их и согласованно объединить, не затирать базы.
   Не копировать WAL/SHM/сокеты с живого старого процесса.
6. Перенести source→target пути в структурированных метаданных Herdr/history,
   cwd/rollout_path SQLite и настройках проектов приложений. Содержимое разговоров
   не переписывать массовой заменой строк: можно сломать offsets нативной истории.
   Для исторических cwd при необходимости временно использовать совместимые
   symlink-алиасы на новые mounts; физические копии остаются в единой раскладке.
7. Проверить чтение нативных Codex-разговоров и Claude CLI/desktop, включая
   архивные, дочерние и не привязанные к Herdr. Сверить UUID, роли и вкладки по
   native session.json И herdr-history. Менеджер и воркер не должны поменяться местами.
8. Только после готовности всех cwd выполнить herdr-service-run и проверить
   штатное восстановление. Не создавать массово новые разговоры вместо resume.
   Проверить Ovis/hp и один согласованный рабочий цикл.

## Регулярный запуск после передачи

`local.mac-backup` — каждый час и при входе; sleep не запрещается. Новые операции
не запускаются параллельно (flock), сеть/SSH имеют таймауты. Без доступного
репозитория новый локальный экспорт не создаётся. Неудачная отправка сохраняет
один неизменный экспорт в pending.json; следующий запуск повторяет его отправку,
после чего очередной часовой запуск снимет уже актуальное состояние. Retention только
для complete: 48 часовых, 30 дневных, 8 недельных, 12 месячных. Partial сохраняются
для разбора и не обновляют last-success; их удаление выполняется отдельно.
Compact освобождает место после prune не чаще раза в неделю.
Ошибка сети или занятого источника не должна удалять предыдущий успешный снимок.

Маркер `~/.config/mac-backup/enabled` разрешает загрузку LaunchAgent на chezmoi apply.
Первично включать после проверки восстановления; на новом Mac — после установки
всех исходных данных. Перед передачей писателя:

```
# На старом Mac
rm ~/.config/mac-backup/enabled
launchctl disable gui/$(id -u)/local.mac-backup
launchctl bootout gui/$(id -u)/local.mac-backup
# На новом после успешной проверки
touch ~/.config/mac-backup/enabled
launchctl enable gui/$(id -u)/local.mac-backup
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.mac-backup.plist
```

Одновременно старый и новый Mac этот репозиторий по расписанию не обновляют.
Другие Ops/watchdog/CI-таймеры это разрешение не включает. Логи:
`~/Library/Logs/mac-backup.log`; состояние: `~/.local/state/mac-backup/status.json`.
Старый `~/Backups/dev/repository` остаётся историческим архивом; ни опроса dev,
ни его таймера на новой машине больше нет.
