# Восстановление dev на макбуке

Бекап находится в `~/Backups/dev/repository` (restic, шифрование и дедупликация).
Ключ сохранён в Bitwarden/rbw в записи **`dev-backup-restic`**.
Локальная копия для автоматического запуска: `~/.config/dev-backup/password`,
права 600. Ключ не хранится в git/chezmoi, Obsidian или на самом dev.
Без ключа расшифровать repository нельзя. При переносе бекапа на другой диск
сохранить доступ к Bitwarden отдельно; пароль мастер-хранилища тоже потребуется.

Если локальный файл ключа утрачен, восстановить его из rbw:

```sh
rbw unlock
umask 077
mkdir -p ~/.config/dev-backup
rbw get dev-backup-restic > ~/.config/dev-backup/password.recovered && \
  mv ~/.config/dev-backup/password.recovered ~/.config/dev-backup/password
chmod 600 ~/.config/dev-backup/password
```

Этот ключ относится к существующему repository. Не генерировать вместо него
новый пароль: новый пароль не расшифрует старые снимки.

## Проверить и извлечь

```sh
dev-backup status
dev-backup snapshots
dev-backup restore --target ~/dev-recovery
```

Целевая папка должна быть новой. Команда извлекает последний `complete`
снимок, проверяет содержимое и не меняет существующие настройки/сессии мака.
Для конкретного снимка: `--snapshot <id>`. Если доступен только аварийный
`partial` снимок, выбрать его точный id — он может содержать неполные экспорты;
смотреть `recovery/manifest.json`.

Если скрипт утрачен, установить restic (`brew install restic`) и выполнить:

```sh
restic -r ~/Backups/dev/repository -p ~/.config/dev-backup/password snapshots
restic -r ~/Backups/dev/repository -p ~/.config/dev-backup/password \
  restore latest \
  --host dev --tag complete --target ~/dev-recovery --verify
```

В восстановленной папке:

- `home/` — dev HOME с исходными относительными путями: Codex/Claude/OpenCode,
  Herdr, системные юниты, watchdog, скрипты, chezmoi, ключи/авторизация.
- `resolved-skills/` — содержимое скиллов; ссылки на Linux/Arc дополнительно
  разыменованы, так что тексты доступны и без dev/Arc.
- `recovery/herdr-agents.json` — актуальные имена, UUID сессий и cwd агентов.
- `recovery/herdr-workspaces.json` — workspace и их идентификаторы.
- `recovery/arc/<name>/` — HEAD, base, ветка, история коммитов, binary patches,
  изменённые/новые файлы, удаления, локальные инструкции/checkpoints.
- `recovery/databases.json` — перечень SQLite-снимков, проверенных `quick_check`.
- `recovery/manifest.json` — время, полнота, ошибки и исходная карта путей.

## Восстановить код

Сначала подключить корпоративную сеть/VPN и убедиться, что Arc на Mac работает.
Сетевой Arcadia/trunk целиком не копируется. На работающих mount мака ничего
не перезаписывать: создать отдельный новый mount для восстанавливаемой задачи.

В `recovery/arc/<name>/manifest.json` записаны `info.hash`, `info.branch`, `base`.
`base` обычно последняя опубликованная ревизия ветки; для новой ветки без remote
это merge-base с trunk. Экспорт сохраняет локальные коммиты после этого base;
опубликованную историю и остальное дерево при восстановлении предоставляет Arc.
Если HEAD уже опубликован, checkout его полного hash в новом mount. Если HEAD
на сервере недоступен, checkout `base`: экспорт содержит итоговые версии всех
изменённых файлов, в том числе бинарных, новые файлы и записи об удалениях.

Из корня НОВОГО дерева на нужной ревизии:

```sh
python3 /path/to/recovery/restore-worktree.py \
  /path/to/recovery/arc/<name> /path/to/NEW-mount
# Проверить preview, затем записать файлы:
python3 /path/to/recovery/restore-worktree.py \
  /path/to/recovery/arc/<name> /path/to/NEW-mount --apply
# Проверить итог:
arc status
```

Патчи сохраняются дополнительно для просмотра staged/unstaged/committed слоёв.
Переносимые экспорты сохраняют рабочее содержимое,
а не обещают воспроизвести индекс Arc/процессы/все промежуточные коммиты.
`restore-worktree.py` копирует сохранённые файлы/инструкции и обрабатывает
удаления в явно указанном НОВОМ дереве; см. `--help`. `files.json` содержит
SHA256, которые скрипт проверяет перед записью. Восстановление файлов
это сохраняет бинарные и untracked файлы, а также локальные checkpoints.

## Восстановить агентов

На Mac уже есть локальный Herdr и web-ui. Использовать macOS/arm64 версии
Codex/Claude/Herdr, не запускать сохранённые Linux/x86_64 бинарники.
Существующие локальные конфиги и сессии сохранить; системные Linux-юниты
на macOS не копировать. launchd-конфиги и установка уже управляются chezmoi.

1. Из `herdr-agents.json` выбрать нужный UUID и новый cwd восстановленного дерева.
2. Скопировать `home/.codex/sessions` и индексы в ОТДЕЛЬНЫЙ `CODEX_HOME`
   (например `~/.codex-dev-recovery`), а не поверх активного `~/.codex`.
   Auth можно использовать текущий macOS либо сохранённый dev; сессии OAuth
   могут потребовать нового входа. Не копировать Linux `config.toml`/`hooks.json`
   без адаптации путей, MCP, executable и trust: использовать конфиг мака,
   подключив восстановленные скиллы и безопасные рабочие пути.
3. Запустить в новой панели Herdr:
   `CODEX_HOME=~/.codex-dev-recovery codex resume -C <new-cwd> <uuid>`.
   Не отправлять агенту продуктовые действия, пока он не перечитает исходный
   role skill, checkpoint, разрешения пользователя и не проверит новый cwd.
4. Claude хранит разговоры в `home/.claude/projects`; имена папок закодированы
   старым cwd. Для нового cwd импортировать соответствующую папку либо
   использовать `CLAUDE_CONFIG_DIR` с отдельной восстановленной конфигурацией
   и `claude --resume <uuid>`; проверить поиск сессии до продолжения работы.
5. OpenCode/watchdog на Mac не включать автоматически: Linux абсолютные пути,
   таймеры и окружение прокси отличаются. История и конфиги сохранены.

Herdr `home/.config/herdr/session.json` полезен как карта расположения панелей,
но содержит Linux cwd и startup-команды. Не подменять им активную сессию мака.
Панели/workspace создать заново и восстановить агентов по UUID.

## Регулярная работа

`local.dev-backup` запускает `dev-backup run` каждые 30 минут и при входе в
сессию macOS. Пока Mac спит/выключен или dev/корпоративная сеть недоступны,
новых копий нет; пропущенный календарный запуск выполняется при пробуждении,
а при отсутствии сети следующий запуск повторяет попытку. Предыдущие снимки
не зависят от доступности dev. Последний успешный бекап: `dev-backup status`.
Лог: `~/Library/Logs/dev-backup.log`.

Сохраняются 48 часовых, 14 дневных, 8 недельных и 6 месячных точек.
Неуспешный запуск не обновляет `last_success` и не сокращает старые копии.
Раз в неделю успешный запуск дополнительно читает/проверяет все блоки и
освобождает невостребованные блоки после retention. Можно запустить вручную:
`dev-backup check`, `dev-backup prune`. Репозиторий и пароль не синхронизируются
через chezmoi; в git лежат только скрипты, таймер и этот документ.

`dev-backup archive` отдельно сохраняет физические локальные Arc refs/objects
и shared object store (включая историю припаркованных веток). Это большой
дополнительный rescue-снимок с тегом `arc-objects`; он не задерживает первый
переносимый бекап. Активные RocksDB overlays не копируются как согласованная
база: они содержат много кэша и меняются у работающего FUSE. Для восстановления
текущих деревьев использовать переносимые экспорты. Raw objects/refs оставлены
для восстановления недоступных локальных commit hash опытным пользователем;
перенос работающего Linux store в macOS автоматически не выполняется.
Дополнительный таймер `local.dev-backup-archive` обновляет этот архив раз в сутки.
Он использует отдельную staging-папку и lock; большие объекты не входят в
каждые 30 минут создаваемые переносимые снимки. Архив имеет свою retention:
7 дневных, 8 недельных и 6 месячных точек.
Старые физические checkout `~/grut`, `~/hatter`, `~/logos_direct`, `~/umr`,
`~/opencode` также входят в ежедневный архив; `.build`, node_modules и прочие
генерируемые файлы исключены. Все текущие Arc/FUSE-деревья сохраняются переносимым
экспортом в основном бекапе каждые 30 минут.

SQLite согласованы по отдельности online backup API. Разговоры JSONL и другие
файлы копируются без остановки агентов: общая точка не транзакционная, последний
незавершённый JSONL record при возобновлении может быть неполным. Экспорт Arc
проверяет, что HEAD/ветка не сменились во время чтения. FUSE/сеть имеют timeout;
ошибки помечаются, а не выдаются за успешное полное восстановление.

Не копируются временные CI-логи/артефакты, node_modules, скачанные дистрибутивы,
Arc FUSE tree/trunk, runtime sockets/locks, временная очередь MCP logs/queue
и shell snapshots с окружением. Очередь меняется во время доставки логов;
конфиги MCP и остальные файлы `.mcp` сохраняются.
Исходные ключи и секреты внутри бекапа — приватные данные: staging и repository
лежат в папке с правами 700; repository дополнительно зашифрован restic.
